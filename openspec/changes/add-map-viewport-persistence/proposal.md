## Why

The map always opens at a fixed center and zoom (11), discarding wherever the user
last looked. On every reload they must re-pan and re-zoom back to their area of
interest. Persisting the viewport makes the map resume where they left off, and a
slightly tighter default zoom (12) frames the Chattanooga area better on first load.

## What Changes

- Change the map's default zoom from **11 to 12** (`DEFAULT_VIEW.zoom` in `MapView.svelte`).
- On map initialization, **restore the last viewport** (`zoom`, `lat`, `lng`) from a new
  `localStorage` key `localdash.map.view`; when absent or unusable, fall back to the
  default center at zoom 12.
- On Leaflet `moveend` / `zoomend`, **save the current viewport** to `localdash.map.view`,
  alongside the existing debug-store publish (which is unchanged).
- Loading is **tolerant**: if any of the three fields is missing, non-numeric, or
  non-finite, the whole default view is used (never a half-restored view). Storage write
  failures are swallowed.
- Deliberately use a **separate key** (`localdash.map.view`), not the existing
  `localdash.map` filter blob: that blob's key-presence flips filtering into allowlist
  mode, so folding viewport in would make merely panning the map silently change future
  source-filtering behavior.
- `flyTo` (table row click → zoom 15) and the detail-track rendering are **unchanged**;
  only zoom and center are persisted.

### Modified Capabilities
- `frontend-timeseries`: the map's default zoom becomes 12, and the map restores its
  viewport from persisted state on load / saves it on `moveend` / `zoomend`.
- `frontend-preferences`: introduce the namespaced `localdash.map.view` key holding
  `{ zoom, lat, lng }`, and relax the "one JSON key per feature" invariant to permit a
  namespaced view-state key with tolerant per-field loading.

## Impact

- `frontend/src/features/timeseries/components/MapView.svelte`: default zoom, viewport
  restore on mount, viewport save on `moveend` / `zoomend`.
- `frontend/src/lib/prefs.svelte.ts`: reused as-is (`loadPrefs`, `savePrefs`, `asNumber`);
  no API change expected.
- New `localStorage` key `localdash.map.view`. No backend, API, or schema changes.
- Frontend build artifact in `static/` regenerated by `vite build` (never hand-edited).
